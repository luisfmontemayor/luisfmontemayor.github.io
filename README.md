# Personal Site: Single-Page Portfolio on GitHub Pages

## 1. System Overview
This repository holds one static site, served at `https://luisfmontemayor.github.io`.

There is **no backend server** and **no runtime Node.js**. The page is a single hand-written `index.html`; web fonts come from Google Fonts at load time. Two things are compiled ahead of time: TypeScript (`src/main.ts` -> `dist/main.js`) for a small progressive-enhancement script, and Tailwind (`src/styles.css` -> `dist/styles.css`) for the stylesheet.

Deployment is **not** a raw serve of the `main` branch. A GitHub Actions workflow (`.github/workflows/deploy.yml`) lints, type-checks, builds, assembles a `_site/` directory, substitutes deploy-time tokens, and publishes that artifact to Pages.

## 2. Repository Layout
```text
luisfmontemayor.github.io/
├── index.html              -> Markup only; no inline config or styles
├── phones.html             -> Local-only preview harness, three synced device widths
├── tailwind.config.js      -> Theme tokens (colours, fonts, radius) and content globs
├── src/styles.css          -> Tailwind directives + the @layer components library
├── src/main.ts             -> Progressive enhancement; compiled to dist/main.js
├── dist/                   -> Build output (gitignored, produced by CI and by `npm run build`)
├── assets/images/          -> Social and Scholar icons (SVG)
├── cv.pdf                  -> Optional; copied by CI only if present
└── .github/workflows/      -> Build and deploy pipeline
```

`dist/` is **not** committed — it is in `.gitignore` and rebuilt by CI on every push. `phones.html` is a development tool and is deliberately not copied into the deployed artifact.

## 3. Deploy-time token substitution
Two things are injected by CI rather than stored in this repo. Both leave placeholder tokens in the committed `index.html`, and both degrade quietly in local previews where nothing substitutes them.

| Token | Source | Handled by |
| --- | --- | --- |
| `__COMMIT_SHA__`, `__COMMIT_SHORT__` | `GITHUB_SHA` | Footer build link; `hideUnstampedCommit()` hides the line when unsubstituted |
| `__EMAIL_U__`, `__EMAIL_D__` | `CONTACT_EMAIL` repo secret | Contact row; `revealEmail()` joins the two base64 halves and sets the `mailto:` |

The contact address is split into base64-encoded local part and domain so the served HTML contains no `@`, no `mailto:`, and nothing matching an email regex. This defeats bulk harvesters that never execute JavaScript; it does not defeat a headless browser that renders the DOM.

**Required setup:** the `CONTACT_EMAIL` secret must exist under Settings > Secrets and variables > Actions. The build fails deliberately if it is unset, rather than shipping a broken address.

## 4. Local Development

### Prerequisites
- Node.js + npm (tooling: TypeScript, Biome, Prettier, Playwright)
- Python 3 (local static server)

### Setup
```bash
npm install
```

### npm scripts
| Script | Command | Purpose |
| --- | --- | --- |
| `npm run build` | `build:ts` -> `build:css` | Full build into `dist/` |
| `npm run build:ts` | `tsc` | Compile `src/main.ts` to `dist/main.js` |
| `npm run build:css` | `tailwindcss -i src/styles.css -o dist/styles.css --minify` | Compile the stylesheet |
| `npm run typecheck` | `tsc --noEmit` | Type-check without emitting |
| `npm run lint` | `biome check .` + `prettier --check "*.html" "src/**/*.css"` | Report lint/format issues |
| `npm run format` | `biome check --write .` + `prettier --write "*.html" "src/**/*.css"` | Apply fixes and formatting |
| `npm run qa` | `format` -> `lint` -> `typecheck` | Full pre-push gate |
| `npm run serve` | `python3 -m http.server 8000` | Serve the site at `http://localhost:8000` |
| `npm run start` | `build` -> `serve` | Build then serve |
| `npm run dev` | `build` -> open browser -> `serve` | Build, open the browser, and serve |
| `npm run phones` | `build` -> open `phones.html` on :8001 | Preview three device widths, scroll-synced |

Serve over HTTP rather than opening `index.html` from the filesystem: `dist/main.js` is loaded as an ES module, and `file://` origins are blocked by CORS.

### Toolchain
- **Tailwind CSS 3.4 LTS** (`tailwind.config.js`) — compiled ahead of time, **not** the Play CDN. The CDN was dropped because it only compiles `@apply`/`@layer` inside an inline `<style type="text/tailwindcss">` block, which no editor tooling can parse as CSS, and because Tailwind documents it as development-only. Utilities are generated by scanning the `content` globs; `src/main.ts` is scanned too, since it toggles `hidden` on the drawer.
- **TypeScript** (`tsconfig.json`) — strict mode with extra safety flags (`noUncheckedIndexedAccess`, `noUnusedLocals`, `exactOptionalPropertyTypes`, `noPropertyAccessFromIndexSignature`, ...). Entry point: `src/main.ts` -> `dist/main.js`.
- **Biome** (`biome.json`) — lints and formats TypeScript and JSON (2-space indent, 100-char line width).
- **Prettier** (`.prettierrc`) — formats HTML and CSS (100-char print width); `*.svg` is ignored via `.prettierignore` so hand-tuned icon fills are left untouched.

Note that `noPropertyAccessFromIndexSignature` and Biome's `useLiteralKeys` give contradictory advice about `dataset` access. `getAttribute("data-*")` satisfies both and is what `src/main.ts` uses.

### Editor integration (VS Code)
`.vscode/settings.json` runs the toolchain on every save:
- Format on save — Biome for `.ts`/`.json`, Prettier for `.html`/`.css`.
- Lint fix + import organization on save via Biome.
- Type errors flagged inline and project-wide in the Problems panel.

`.vscode/extensions.json` recommends the required extensions; accept the prompt to install them.

| Extension | Provides |
| --- | --- |
| `biomejs.biome` | Lint/format for `.ts`, `.js`, `.json` |
| `esbenp.prettier-vscode` | Format for `.html`, `.css` |
| `bradlc.vscode-tailwindcss` | Utility-class completion and hover, driven by `tailwind.config.js` |
| `ecmel.vscode-html-css` | **Go to Definition** from a `class="..."` name to its rule in `src/styles.css` |

Go to Definition on a class name needs all of: a real `.css` file (not an inline block), the `ecmel.vscode-html-css` extension, and `"css.styleSheets": ["src/styles.css"]` in `.vscode/settings.json` pointing it at the source rather than the built output. `"css.lint.unknownAtRules": "ignore"` suppresses the false errors the built-in CSS service raises on `@tailwind` and `@apply`.
